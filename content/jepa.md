# JEPA：学习对预测与决策有用的状态表征

> 阅读定位：你已经熟悉 encoder、decoder、LLM 与 agent。本路线聚焦一个更具体的问题：面对复杂观测，怎样学到既能压缩冗余、又保留后续预测所需信息的状态？本文是原始论文与官方代码的导读，未独立复现实验。核验日期：2026-10-01。

## 路线总览

### 先决定哪些信息必须留下

在 IT 系统中，“状态”不等于一张监控截图，也不等于把所有日志拼进 prompt。它需要同时概括当前负载、资源约束、依赖关系和变化趋势。可观测数据很大，真正影响某个预测或操作的因素却可能很少。JEPA 路线让我们关注表征的选择：模型应该在什么空间里预测，哪些细节可以忽略，哪些局部变化必须保留？这是面向 IT 的阅读视角，并非下列视觉论文已经验证的应用。

JEPA 的基本训练任务是在表示空间补全缺失信息。在线 encoder 处理可见部分，predictor 接收这些表示与目标位置，预测被遮挡部分的表示；目标来自缓慢更新的 target encoder，并阻断该分支的梯度。V-JEPA 的回归目标不是像素。关键结构与损失可查看 [V-JEPA 原文 §3、Figure 3](https://arxiv.org/html/2404.08471v1)。

上述流程解释的是表征学习。只有把过去观测、动作及必要的系统状态接入时间方向明确的 predictor，才能形成用于控制的动作条件模型。V-JEPA 2-AC 的后训练与规划属于这个扩展，不能把普通遮挡补全模型直接当成操作后果模拟器。[V-JEPA 2 原文 §3、Figure 2](https://arxiv.org/html/2506.09985v1)。

两个训练目标不必排斥生成式或结构化模型。JEPA 可以提供状态 encoder，图模型可以表达依赖结构，动作模型可以做多步预测，生成 decoder 可以将结果转成可检查的观测。这些是可组合的设计维度；是否值得组合，应由目标任务与证据决定。

### 怎样阅读这条路线的证据

表征能支持分类，说明某类信息可以被读出；支持未来类别预测，说明它在特定数据和时间范围内包含可用预测信息；进入闭环控制并成功，才进一步说明整个系统能在对应实验条件下选择有效动作。三种证据不能互相替代。

| 证据层次 | 阅读时应核对的条件 | 仍然没有自动解决的问题 |
| --- | --- | --- |
| 冻结 encoder 后训练 probe | probe 是否使用标签、容量多大、评估视图与训练数据 | 无监督训练不意味着下游评估零标签 |
| 根据过去预测未来类别 | 预测间隔、候选词表、数据领域、Top-k 指标 | 开放环境的多步后果与未见动作 |
| 动作条件预测与闭环规划 | 动作数据、目标形式、控制器、规划预算、任务与试验次数 | 任意操作的干预效应、跨域可靠性和安全保证 |
| 局部稠密特征与几何 probe | 读出器、监督数据、模型规模、局部指标 | 学到可解释的物理变量或因果结构 |

阅读时还要区分 attention 中的 causal mask 与统计意义的 causal identification。前者约束模型不能读取未来输入；后者要求针对干预效应有足够的数据与识别条件。使用动作作为输入会改变预测任务，但“给模型输入动作”本身并不消除隐藏混杂，也不保证训练中没有出现的操作能被可靠评估。这里是方法层面的分析，不能把论文中对物理直觉或动作作用的描述升级为已完成因果识别。

### 阅读顺序与进入 IT 的问题

1. 先读下面的 V-JEPA（2024），弄清目标表示、mask、EMA 与 probe 的关系。需要图像版锚点时，可补读 [I-JEPA（2023，原始论文入口）](https://arxiv.org/abs/2301.08243)。
2. 接着读 V-JEPA 2（2025）的 §2 与 §3，再看 §4 的实验条件。重点理解从表征预训练到动作条件后训练新增了什么数据与结构。
3. 最后读 V-JEPA 2.1（2026）的 §2 与 Table 1，再看 §3.2–3.3。它提醒我们：全局预测表现强，局部状态质量仍可能不足；最佳 headline 也可能改变模型规模或规划预算。

迁移到云系统时，可把问题拆成“能否预测”和“能否据此控制”。前者可以从公开遥测开始，检验表示是否保留延迟、饱和程度与依赖变化；后者需要包含动作、执行时刻、执行结果和后续观测的交互轨迹。RCA 的根因标签只能回答诊断任务，不能替代多个恢复动作的状态转移数据。把服务重启后恰好恢复的一段日志交给预测器，也不能直接证明重启造成恢复。

一个公开、可讨论的研究检查是：在类似总吞吐的全局读出之外，加入服务级或链路级状态读出，并测试一个局部瓶颈是否被表示忽略；如果两个潜在状态在当前观测中很像、但对同一操作的响应不同，还应检查历史信息能否区分它们。这些是面向 IT 的分析建议，本文没有报告对应实验结果。

## V-JEPA

**2024 · 表征预测能否单独成为有效的视频预训练目标？**

**原文**：[Revisiting Feature Prediction for Learning Visual Representations from Video，arXiv:2404.08471v1](https://arxiv.org/html/2404.08471v1) · **代码**：[facebookresearch/jepa](https://github.com/facebookresearch/jepa)。

### 问题与机制

论文检验不使用文本、负样本或像素重建的特征预测能否学到有效视频表示。它沿用上面的双 encoder 流程：mask 连续时空区域，predictor 利用可见 token 与目标位置回归 EMA teacher 的表示，使用 L1 损失。目标分支观看完整视频后再抽取目标位置，和在线分支只见可见区域的条件不同。[原文 §3.1–3.3、Figure 3](https://arxiv.org/html/2404.08471v1)。

教学上，重点不是“向量比像素更聪明”，而是 target encoder 也在学习怎样表达数据。预测器和表示共同变化，使任务可以减少对某些细节的依赖；这种自由度也要求检查信息丢失与表示坍缩。训练误差小并不能单独说明状态有用。

### 训练、实验与主要发现

VideoMix2M 汇合 HowTo100M、Kinetics 与 Something-Something-v2 的约 200 万视频，移除指定验证集的重叠。模型读取 16 帧短片段。Table 1 在相同 ViT-L、多块遮挡、90K iterations 下比较目标：冻结 backbone、单视图 attentive probe 的 K400 分数为特征目标 73.7、像素目标 68.6；K400 全量微调为 85.6 与 85.4。[原文 §3.4、§4.1、Table 1](https://arxiv.org/html/2404.08471v1)。

这个对照支持“特征预测产生更易读出的表示”，但全量微调差距很小，不能概括成所有使用方式都大幅优于像素预测。probe 经过下游监督训练；冻结指 backbone 不更新，不是整个评估流程没有标签。官方仓库提供预训练与评估入口，可用于后续检查实现与配置；本导读没有运行它们。[官方 README](https://github.com/facebookresearch/jepa)。

### 局限与 IT 迁移分析

首先，遮挡补全没有显式接收操作者的控制动作。把它用于识别视频内容与把它用于比较“扩容还是回滚”是不同的问题；前者的 benchmark 无法给后者背书。其次，任务所需要的细节不能仅以可预测性判断。在 IT 中，一个罕见错误码可能不利于平均预测误差，却决定某次恢复动作是否安全。表示设计需要用局部状态与决策需求共同检查。

论文 §6 的可视化额外训练 diffusion decoder，将冻结的预测表示转回像素；这是定性读出实验，不能据此把 V-JEPA 的预训练器描述为直接生成视频的模型。[原文 §6、Figure 6](https://arxiv.org/html/2404.08471v1)。

面向 IT 的合理价值是借鉴“先学习可预测状态、再验证状态是否保留任务信息”的思路。视觉的 token、mask 与数据增强未必适合时间戳、调用拓扑和异步日志。迁移实验需要重新规定遮挡单位，并防止预测目标泄漏未来时间的信息。能检测某类故障不等于能模拟恢复操作。

**建议带着一个问题读原文**：Table 1 中，为什么冻结读出优势明显，端到端微调差距却较小？它将“学习到什么”与“读出器可以补偿什么”分开，是进入表征研究的关键。

## V-JEPA 2

**2025 · 从视频表示走向动作条件预测与规划**

**原文**：[V-JEPA 2: Self-Supervised Video Models Enable Understanding, Prediction and Planning，arXiv:2506.09985v1](https://arxiv.org/html/2506.09985v1) · **代码**：[facebookresearch/vjepa2](https://github.com/facebookresearch/vjepa2)。

### 问题与机制

V-JEPA 2 扩大表征预训练，再单独建立 V-JEPA 2-AC。动作条件阶段冻结视觉 encoder，用时间因果 predictor 根据历史表示、末端状态和动作预测后续表示。规划通过 CEM 寻找接近目标图像表示的动作，执行第一个动作后重新观察、规划。[原文 Figure 2、§3、Figure 7](https://arxiv.org/html/2506.09985v1)。

这一步使“状态学习”与“如何操作”之间的接口具体化：预训练给出表示，交互数据给出状态和动作如何相连，目标表示给出规划准则。因此，互联网视频预训练与机器人动作条件模型是相关但不同的成果。下游 action anticipation 中的 action 是人类活动类别；机器人控制输入中的 action 是末端控制量，二者不能混读。

### 训练与实验条件

预训练使用超过 100 万小时视频。2-AC 使用 DROID 的不足 62 小时交互视频与末端状态，动作由相邻状态变化构造。“无标签”指不用任务、奖励或成功标签，并非没有状态和动作信号。[原文 §2、§3.1](https://arxiv.org/html/2506.09985v1)。

机器人测试在两个未进入 DROID 的实验室，使用 Franka 桌面臂、单目 RGB 与视觉目标；抓取和放置任务每项 10 次。放置还提供中间目标图，所用规划 horizon 为 1。作者人工选择可工作的相机位置，并明确讨论相机敏感性、长时规划与图像目标限制。[原文 §4、Tables 2–3、Appendix B.2](https://arxiv.org/html/2506.09985v1)。

### 主要发现与证据怎么读

官方项目分开发布 encoder、probe 与 AC checkpoint。SSv2 的 77.3 是 probe 分类表现；EK100 的 39.7 是未来动作类别的 Recall@5；AC 则进入机器人闭环控制。它们分别检验表示、类别预测与规划，不能混成一个“世界模型能力分数”。[官方项目 README 的 Pre-training、Post-training 与 Evaluation Attentive Probes](https://github.com/facebookresearch/vjepa2)。

能在未参与后训练的实验室成功选择动作，是实际闭环证据，比只看生成视频更接近控制用途。它仍属于特定机械臂、动作空间、视觉目标与规划方式下的测试。10 次试验使成功率以 10 个百分点变化；少数任务中的差值不能承担很广泛的鲁棒性结论。给定子目标也承担了一部分任务分解工作，“zero-shot”需按没有新实验室训练数据的含义理解。

### 局限与 IT 迁移分析

对云系统，最有价值的启发是分阶段建模接口：可以先从遥测学习表示，再用真实或仿真的操作轨迹学习动作条件转移。但是，没有交互轨迹时，不能把观察性指标趋势预测包装成恢复动作评估。运维动作还带执行延迟、失败、权限与多个并发操作者，简单的状态差未必对应一个明确操作。

另一个问题是目标空间。机器人可以提供目标图；“延迟恢复且没有丢单”的运维目标需要兼顾多个可测约束。仅最小化 latent distance 可能偏好视觉或统计上相似的状态，却没有达到业务约束。因此 IT 迁移需要验证预测表示与真实目标之间的关系，记录动作覆盖，检查多步误差与超出数据范围的操作。论文没有验证云运维的干预识别或生产安全性。

**建议阅读**：先沿 Figure 2 看两阶段，再沿 Figure 7 看闭环，最后读 §4.3 和 Appendix B.2。这样会发现：模型、子目标、控制器和实验环境共同构成演示系统。

## V-JEPA 2.1

**2026 · 全局理解之外，局部状态还保留得好吗？**

**所读版本**：[V-JEPA 2.1: Unlocking Dense Features in Video Self-Supervised Learning，arXiv:2603.14482v3](https://arxiv.org/html/2603.14482v3)，首发 2026-03-15，所读 v3 更新于 2026-06-11。[版本记录](https://arxiv.org/abs/2603.14482)。**代码**：[facebookresearch/vjepa2](https://github.com/facebookresearch/vjepa2)。

### 问题、机制与数据

2.1 聚焦稠密表征：给可见 context token 也加预测损失，并按距遮挡区域的距离加权；多层 self-supervision 监督中间 encoder 表示。配合图像/视频各自的 tokenizer、VisionMix163M 数据和模型扩展，使局部与全局信息共同学习。Figure 4 是机制总图，Table 1 给逐项消融。[原文 §2.2–2.3、Figure 4、Table 1](https://arxiv.org/html/2603.14482v3)。

读这项设计时，可以问：如果每个可见 token 只被当成帮助补全目标的工作空间，它是否还需要忠实代表本位置？2.1 的思路是让局部位置也承受明确监督。对 IT 的对应问题是：一份表示擅长读出全局健康度，是否仍然保留具体服务的队列与资源差异？这是迁移类比，并非论文对 IT 的实验结论。

### 实验条件与主要发现

EK100 Table 5 中，同为 1B 的 2.1 得 38.4 Action Recall@5，2 得 39.7；2.1 的 40.8 来自 2B 模型。机器人 Table 6 同规划设置的抓取为 60%→70%；改用 horizon 8 后为 80%，单步规划由 3 秒增至 14 秒。每项只评估 10 个任务。[原文 §3.2–3.3、Tables 5–6](https://arxiv.org/html/2603.14482v3)。

因此不能把“40.8”写成同规模算法全面提升，也不能把“+20 个百分点抓取”写成固定预算只换 encoder 的收益。表征、模型规模与规划器相互影响；更长规划可用是有价值的观察，但效果归因要分开。作者 Table 6 的表注概括 20%，正文又分别解释同设置的 10% 与长规划结果，应优先报告具体行和条件。

官方代码把 2.1 的预训练模块与动作条件后训练模块分开，并发布 80M–2B 不同规模 checkpoint。执行机器人任务仍需动作条件 predictor 和 MPC，不能从稠密 feature checkpoint 直接推出控制能力。[官方 README：V-JEPA 2.1 Pre-training、Models、Code Structure](https://github.com/facebookresearch/vjepa2)。

### 边界与 IT 迁移分析

稠密特征连贯、局部 probe 有用，是对状态表示质量的证据；它不等于每个维度对应真实状态变量，也不说明模型识别了因果关系。对运维，最应保留的局部细节可能是低频错误、一个依赖边的时延或局部配置，不能由视觉上连续的 feature map 自动替代。

这项工作也提示一种常见误读：加入更多局部损失可能改变全局任务的取舍，多层监督和数据扩展共同补偿这种变化。因此迁移时应先明确什么叫“局部”与“全局”，再用控制变量的实验检查收益。把最终最大的模型与较小旧模型比较，可以展示系统上限，却不能单独识别每个机制的贡献。

对于云系统，可考虑同时读出全局业务指标和服务级状态，并测试表示能否支持动作后果预测。还需要跨拓扑、跨负载和跨时间的测试，检查局部表示不会把关键异常平均掉。这里提出的是证据需求；当前导读未做 IT 训练、部署或复现，也没有把这篇论文写成生产控制方案。

**建议阅读**：先看 Table 1 的逐项消融，再看 Table 5 的同规模行，最后看 Table 6 的预算变化。Figure 1 的 PCA 可帮助观察局部结构，但颜色连贯不能替代量化任务和闭环实验。
